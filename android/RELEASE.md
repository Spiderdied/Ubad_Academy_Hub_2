# Building UBAD Academy Hub for Android

All commands run from the `android/` directory (the Gradle project root). The
Gradle wrapper is committed, so no local Gradle install is needed — only a JDK 17
and an Android SDK with platform 36 + build-tools.

## Build commands

| What | Command | Output |
| --- | --- | --- |
| Debug APK | `./gradlew :app:assembleDebug` | `android/app/build/outputs/apk/debug/app-debug.apk` |
| Release APK (R8) | `./gradlew :app:assembleRelease` | `android/app/build/outputs/apk/release/app-release.apk` |
| Release AAB (Play) | `./gradlew :app:bundleRelease` | `android/app/build/outputs/bundle/release/app-release.aab` |
| Unit tests | `./gradlew :app:testDebugUnitTest` | `android/app/build/reports/tests/testDebugUnitTest/index.html` |
| R8 mapping (keep it) | produced by `assembleRelease` | `android/app/build/outputs/mapping/release/mapping.txt` |

Debug and release together:

```bash
cd android
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:assembleRelease :app:bundleRelease
```

Note the release APK is **unsigned** unless a signing config is supplied (see
below); `assembleRelease` still succeeds and produces an unsigned APK, which is
what the CI smoke job signs with a throwaway key.

## Signing (never committed)

Supply either `android/keystore.properties` (git-ignored) or environment
variables. Environment variables win.

`android/keystore.properties`:

```properties
storeFile=/absolute/path/to/ubad-release.jks
storePassword=…
keyAlias=ubad
keyPassword=…
```

Environment variables: `UBAD_KEYSTORE_FILE`, `UBAD_KEYSTORE_PASSWORD`,
`UBAD_KEY_ALIAS`, `UBAD_KEY_PASSWORD`.

With no signing config the release build stays unsigned rather than falling back
to the debug key — a build that silently ships debug-signed is worse than one
that fails a Play upload. `keystore.properties` and `*.jks`/`*.keystore` are
git-ignored; never commit them.

## Cloud configuration

The app ships the project's **public** Firebase client config (the same values
the web app already serves in `firebase-auth.js` / `index.html`) as defaults, so
a plain `./gradlew assembleRelease` produces a build with cloud sync available.
Override per build via Gradle property (`-Pubad.…`) or environment variable:

| Value | Gradle property | Environment variable | Default |
| --- | --- | --- | --- |
| Firebase project id | `ubad.firebaseProjectId` | `UBAD_FIREBASE_PROJECT_ID` | `ubad-academy-hub` |
| Firebase web API key | `ubad.firebaseWebApiKey` | `UBAD_FIREBASE_WEB_API_KEY` | project's public web key |
| Firebase app id | `ubad.firebaseAppId` | `UBAD_FIREBASE_APP_ID` | project's public web app id |
| Firebase sender id | `ubad.firebaseSenderId` | `UBAD_FIREBASE_SENDER_ID` | `595289164594` |
| Storage bucket | `ubad.firebaseStorageBucket` | `UBAD_FIREBASE_STORAGE_BUCKET` | project bucket |
| Auth domain | `ubad.firebaseAuthDomain` | `UBAD_FIREBASE_AUTH_DOMAIN` | project auth domain |
| B2 Worker URL | `ubad.workerUrl` | `UBAD_WORKER_URL` | project Worker |
| **Google web client id** | `ubad.googleWebClientId` | `UBAD_GOOGLE_WEB_CLIENT_ID` | **none** |

`UBAD_GOOGLE_WEB_CLIENT_ID` has no default and cannot be derived: it is the
OAuth **web** client id from the Firebase console (Authentication → Sign-in
method → Google → Web SDK configuration). Supply it to enable Google sign-in:

```bash
cd android
./gradlew :app:assembleRelease -Pubad.googleWebClientId=123456789012-abcdef.apps.googleusercontent.com
```

Without it the app builds and runs normally, but Settings says that Google
sign-in needs the web client id instead of offering a button that fails on tap.
No secret is involved — but the release keystore's SHA-1 must be registered in
the Firebase console (Project settings → Your apps → Add fingerprint) for
Google sign-in to accept requests from a release build.

Never commit `google-services.json`: the repo's security scan rejects tracked
copies of it, and the app initialises Firebase manually from the values above.

## What must not change

- `Room.databaseBuilder(...)` with no `fallbackToDestructiveMigration`. A schema
  change requires bumping `@Database(version = …)` **and** adding a `Migration`;
  otherwise Room throws on open. Silently wiping user data on update is the one
  failure this project treats as a release blocker, and the smoke suite asserts
  data survives an install-over-existing-data update.
- `android/app/src/main/res/values/strings_web.xml` is generated by
  `node tools/i18n-to-android.js` (run from the repository root). Hand edits are
  overwritten; put Android-only strings in `strings_cloud.xml` instead.
- `firestore.rules` / `storage.rules` are owner-only and must not be relaxed.
